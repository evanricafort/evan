COOP Tabnabbing PoC

Demonstrates a missing Cross-Origin-Opener-Policy: a window opened from this page keeps an opener reference, so this page can silently navigate it somewhere else.

How it works

The target is opened in a named window. Five seconds later this page uses the handle it kept to point that window at a harmless landing page. A target that sends Cross-Origin-Opener-Policy: same-origin severs the handle and is unaffected.

Use it only against sites you are authorised to test.

Can also be passed as ?target= in the URL, which launches on load.

The fix, applied on this site

This PoC exists because evanricafort.com itself had the reverse-tabnabbing half of this bug: every outbound target="_blank" link (62 of them, across the homepage and a couple of tool pages) opened without rel="noopener", so any of those destinations could have used window.opener.location to quietly redirect this tab to a phishing page while the new tab held focus. That's now fixed sitewide.

Done — opener side

Every target="_blank" anchor on this site now carries rel="noopener noreferrer", which severs the new tab's window.opener reference back to this page.

Pending — target side

This site should also send Cross-Origin-Opener-Policy: same-origin as a response header, so it stays isolated if someone else's page opens it without noopener. That header can't be set from a static file — it needs to be added at the edge (this site is fronted by Cloudflare in front of GitHub Pages), via a Transform Rule or Worker.

Both matter because the failure mode isn't symmetric: rel="noopener" protects people who click links out of this site; the COOP header protects this site when it's the one being linked into. This page's Launch button reproduces the second scenario against any URL you give it.
